# 2026-07-27 人差し指でボタンを押す（ポーク）操作の違和感

ハンドトラッキングで UI を直接押せるようにした（`modules/xr/PokeInteraction.js`）あと、
実機で触って出た違和感を3回に分けて潰した。**原因はそれぞれ別物**だったので、順に記録する。

---

## 1. 押すのに指をボタンの裏まで突き抜けさせる必要があった

### 問題

見た目に指がボタン面へ触れても反応せず、**ボタンの後ろまで指を持っていって初めて**押される。

### 原因

`XRFrame.getJointPose()` が返す位置は **指先の中心**であって、指の表面ではない。
これを点として扱っていたため、実際には触れて見える時点で判定点はまだ面の手前にいた。

```
指の表面が面に触れる     … 判定点は面から radius(≈8mm) 手前
そこから PRESS_DEPTH(5mm) … 合計 13mm 押し込んで初めて発火
```

VR には触覚が無いので、この 13mm は「いつ触れたか」の手がかりが一切ないまま進む区間になる。

### 修正

`XRJointPose.radius` を引いて、**指の表面**を基準に測るようにした（`faceDepth()`）。
ランタイムが radius を返さない場合だけ 8mm を仮定する。

---

## 2. それでもまだ深かった

### 問題

半径ぶんを補正してもまだ「押した見た目」より奥で発火する。

### 原因

判定点が `index-finger-tip` の**1点だけ**だった。この joint は**爪の先**にある。

パネルを指で押すとき、指を面に対して寝かせると**最終節の腹が先に接触する**。
そのとき爪の先はまだ面から離れているので、腹で押している感覚と判定がズレる。

### 修正

接触点を2つにした（`CONTACT_JOINTS`）。

- `index-finger-tip`（爪の先）
- `index-finger-phalanx-distal`（第1関節）

**深く入っている方**を採用する。これで指の角度によらず、見た目に触れたところで発火する。
あわせて `PRESS_DEPTH` を 5mm → 1mm に下げた。

---

## 3. 押したあとから光りはじめて見える

### 問題

指がボタンを**貫通してからホバー表示が出る**。押下判定より後にホバーが見える。

### 原因

ホバーが閾値の 2 値で、`hoverSpring`（stiffness 190 / damping 26）の立ち上がりに 200ms 以上かかる。
押す動作は速いので、光が育ちきる前に指が面を通り抜ける。

### 一度やって戻した修正（重要）

**距離に応じてホバー強度を連続的に上げる**ようにした（70mm から徐々に、接触で最大）。
`GlassSurface.setHovered()` を `0..1` の連続値も受け付けるよう拡張。

これは**間違いだった**。ホバー判定が成立していない距離でも色が動くため、
「ホバーしていないのに色が変わる = ボタンが勝手に光っている」という別の違和感を生む。
中間状態を可視化してはいけない、というのがここでの学び。

### 最終的な修正

2 値に戻したうえで、**閾値そのものを手前に出した**。

```js
const HOVER_ENTER = 0.05;  // 50mm まで近づいたらホバー ON
const HOVER_EXIT  = 0.07;  // 70mm まで戻したら OFF
```

2 つの値に差をつけてあるのは、境目に手を置いたときのちらつき防止
（1 つの値だと指の微振動で点滅する）。

ラッチは **手ごとに 1 つのボタン**だけ持つ（`PokeTracker.hovering: Map<handedness, key>`）。
`"<hand>:<key>"` をキーにすると、別のボタンへ移ったときに前のボタンの状態が残り、
戻ってきたときに解除側の閾値が使われてしまう。

## 副次的な変更

### `GlassSurface.setActiveTint()` の追加（`modules/ui/liquidGlass.js`）

上記とは別に「待機中は無彩色、触れたときだけ色が乗る」という要望があり、
待機色とアクティブ色を hover/press の Spring 値で補間する仕組みを入れた。

**状態表示だけは色を保つ**必要がある（触れていなくても状態が読めなければ意味がない）。

| | 扱い |
|---|---|
| Generate 待機 | graphite → 触れると green / orange |
| Generate 生成中 | slate 固定（`setActiveTint(null)`） |
| Talk 待機 / ピン OFF | graphite 固定。色はアクセントの滲みのみ（Clear と同じ） |
| Talk 録音中 | red 固定 |
| ピン ON | green 固定 |

### 試して外したもの: `setActiveOpacity()`

ホバー時にガラスの濃度も上げる仕組みを一度入れたが、
これは **3 の症状（ホバーが機能していないように見える）を濃さで補おうとしたもの**だった。
原因が直った時点で不要になったので、API ごと削除した。

## 補足: ポーク姿勢と握り姿勢の衝突

`modules/xr/HandGrab.js` の Palm Grab 判定と両立させるために、両側に条件が要る。

指差し（人差し指だけ伸ばして他 3 本は握る）の姿勢は、
4 本の curl を**平均すると拳とまったく同じ値**になる。素直に平均すると
ボタンを押すたびに物を掴んでしまう。

- 掴み側: 実効 curl = `min(人差し指, 平均)` として人差し指に拒否権を持たせた
- ポーク側: 人差し指の curl が `MAX_CURL`(0.6) を超えていたら判定しない

これで握った手が面を通り抜けても押されない。
