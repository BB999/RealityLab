# 2026-07-27 大きいモジュールが近くのモジュールを掴めなくする問題

## 問題

three.js で生成したモジュールを大きくすると、**その近くにある別のモジュールをコントローラーで掴めなくなる**。
大きいほうばかりが掴まれてしまう。

## 原因

原因は2つあり、両方が重なって起きていた。

### 1. つかみ判定に一律の下駄を履かせていた

`ModuleManager.findModuleAtPosition`（`modules/ModuleManager.js`）は、
バウンディングボックスの半径を 0.5m で頭打ちにしたうえで、**さらに全方向へ 0.2m 拡張**していた。

```js
const clampedHalfSize = new THREE.Vector3(
  Math.min(size.x / 2, MAX_GRAB_SIZE), ...      // 上限 0.5
);
clampedBox.expandByScalar(radius);              // + 0.2 を無条件で
```

0.2m の下駄は「小さいものを掴みやすくする」ための調整だが、無条件なので大きいものにも乗る。
結果、1m を超えるモジュールのつかみ判定は **一辺 1.4m** にまで膨らんでいた。

### 2. 最初に見つかったものを返していた ← これが本体

判定領域が重なったとき、`for ... return` で**最初にヒットしたモジュールをそのまま返して**いた。
`this.modules` は Map なので、これは実質「**先にスポーンしたほうが勝つ**」という意味になる。

つまり大きいモジュールが先に置かれていると、その 1.4m の領域の中にある小さいモジュールは、
手を直接その上に置いても永久に掴めない。

**同じ欠陥がレーザー側にもあった。** `raycastModules`（`modules/xr/Raycast.js`）も
最初にヒットしたモジュールで打ち切っており、手前・奥を見ていなかった。
奥にある大きなモジュールが、手前の小さなモジュールより先に登録されていれば、そちらが掴まれる。

## 修正

### `modules/ModuleManager.js` — `findModuleAtPosition`

- **下駄を「下限」に変え、上乗せをやめた**。第2引数の意味を「拡張量」から「最小半径」に変更。
  判定半径は `clamp(実寸 / 2, 最小半径, 0.5) + 0.04` になった

  | 実寸 | 旧・判定半径 | 新・判定半径 |
  |---|---|---|
  | 0.1m | 0.25 | 0.24 |
  | 0.5m | 0.45 | 0.29 |
  | 1m 以上 | 0.70 | 0.54 |

  小さいものの掴みやすさは維持したまま、大きいものの余分な範囲だけが減る

- **重なったときは手に近いほうを選ぶ**ようにした（中心までの距離が最小のものを返す）
- 描画物を持たないモジュール（`Box3` が空 → 中心が NaN）を除外
- グリップを握っている間ずっと呼ばれるため、`Box3` / `Vector3` をモジュールスコープで使い回すよう変更

### `modules/xr/Raycast.js` — `raycastModules`

最初のヒットで `return` せず、**全モジュールを見て一番手前を返す**ようにした。

## 検証

大 (2m, 先に登録) と小 (0.1m, 0.6m 離れた位置) を並べて実測。

| 手の位置 | 旧 | 新 |
|---|---|---|
| 小の真上 (0.6, 0, 0) | **big** ← バグ | small |
| 小のすぐ横 (0.7, 0, 0) | big | small |
| 大の中心 (0.1, 0, 0) | big | big |
| 大の内側 (0.35, 0, 0) | big | big |
| どちらの外 (1.2, 0, 0) | null | null |

## 補足: 直っていないもの

つかみ判定の半径には依然 0.5m の上限がある。
これは巨大なモジュールが周囲すべてを飲み込むのを防ぐためだが、
裏返すと **2m のモジュールは中心付近しか直接掴めない**（端に手を伸ばしても反応しない）。
端を掴みたい場合はレーザー（実メッシュ判定・射程10m）を使う。
